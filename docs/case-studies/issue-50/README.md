## Research and component choices

- [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) can remove the long-lived publish token **after** the package exists. The first publish still needs an npm account owner to supply a scoped bootstrap token, then configure the repository/workflow as the trusted publisher and revoke the token.
- [Playwright browser contexts](https://playwright.dev/docs/browser-contexts) isolate public-site audits and permit DOM-based replay. The existing Browser Commander boundary, private checkpoints, per-domain pacing, and no-challenge-bypass policy already provide the required manual runner; source-specific selectors and coverage checks are preferable to an additional scraping dependency.
- [mtcute's sign-in guide](https://mtcute.dev/guide/intro/sign-in) and [API reference](https://ref.mtcute.dev/) support native login and capability tests. A GramJS string session is not evidence of a native mtcute runtime; the operator must perform explicit login into protected local state and pin independently authenticated identities.
- [link-cli/clink](https://github.com/link-foundation/link-cli) is the canonical binary projection tool already used by the project. Replacing it with an unverified JSON mirror would break the issue's LiNo authority and export-verification requirements. Profile its import, reference creation, transaction, export, and snapshot work on the retained private corpus before choosing incremental projection or a documented faster path.
