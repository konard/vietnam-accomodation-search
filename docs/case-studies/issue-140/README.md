## Existing components and primary-source research

- **Telegram SDKs:** reuse mtcute for native ingestion and the existing teleproto/GramJS audit client. Telegram describes custom folders as dialog filters with explicit peers, category flags and exclusions. Their IDs cannot be substituted for active/archive peer folders. This supports the client-side resolver rather than a new folder library. [Telegram folder documentation](https://core.telegram.org/api/folders), [dialogFilter constructor](https://core.telegram.org/constructor/dialogFilter).
- **Native retry:** mtcute documents automatic waits below a configured threshold, so lazy iteration still needs an application retry boundary for longer waits and durable progress. SDK source was inspected for Unix-second history offsets and photo download cancellation. [mtcute error handling](https://mtcute.dev/guide/intro/errors).
- **OCR:** reuse Tesseract CLI. Mode 6 assumes a single text block; mode 11 finds sparse text, which fits scattered poster labels. Language models are explicit production dependencies. Tesseract.js is a viable WASM alternative with worker lifecycle control, but introducing a second engine would add download/runtime complexity without proving the unavailable poster. [Tesseract quality guidance](https://github.com/tesseract-ocr/tessdoc/blob/main/ImproveQuality.md), [CLI documentation](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html), [Tesseract.js](https://github.com/naptha/tesseract.js).
- **Unicode:** use the built-in NFKC normalization and Intl.Segmenter, mapping normalized grapheme positions back to original UTF-16 spans. Compatibility normalization belongs to lexical parsing; applying it to stored contact/URL/property evidence could change identity. [Unicode normalization standard](https://www.unicode.org/reports/tr15/).
- **Dates:** Chrono supports reference-based parsing and several languages and is a plausible future component. A small labelled UTC parser was selected here because arbitrary natural-language date extraction would also recognize contact IDs, contract dates and ambiguous ranges. [Chrono project and API](https://github.com/wanasit/chrono).
- **Publishing:** npm trusted publishing requires a package-level trust relationship with the exact owner/repository/workflow; adding id-token permission alone does not configure it. The workflow already supports an NPM_TOKEN bootstrap, followed by OIDC. Owner-managed secrets and registry access are required; the existing fail-closed preflight must remain. [npm trusted publishing documentation](https://docs.npmjs.com/trusted-publishers/).
- **Processes/storage:** retain Node child_process for native argv and cancellation and the existing LiNo/LinksStore/Rust clink stack. A semantic capability probe is stronger than a help/version string and needs no additional dependency. [Node child process documentation](https://nodejs.org/api/child_process.html), [Rust link-cli](https://github.com/link-foundation/link-cli).

## Verification and evidence limits

Minimum reproductions were run before the fixes; their local logs are preserved outside committed sources. New tests use synthetic/redacted text and finite inputs. No private browser/session/history artifacts or credentials are committed. CI logs are retained in ignored ci-logs/.

Final local validation passed: **1,266 Node tests with 100% production line coverage**, **1,266 Bun tests**, and **1,161 Deno tests plus 19 steps**. The real-clink requirement was enabled for Node/Bun, and the supported Rust 0.2.11 binary was on PATH. Lint, formatting, duplication (5.38%, below the unchanged 10% limit), tracked-file size, syntax and documentation gates passed. The final negative controls also reproduce and prevent next-line/area bedroom counts, Unicode-dash floor/date ranges in both orders and truncated invalid English date tokens.

The initial branch Checks run 37565433272 failed because the prepared dummy commit had no changeset; the patch changeset addresses that requirement. Historical main run 37539841580 cancelled the Windows literal-argument test after 30,002.8774 ms, within an otherwise sufficient job budget (log lines 24413–24416 and 24531–24536). No shell-injection or corrupted-message claim follows from that timeout.

The first implementation run [37569025936](https://github.com/konard/vietnam-accomodation-search/actions/runs/37569025936), created after commit e412655, passed all nine Node/Bun/Deno platform jobs except the Ubuntu coverage gate. Its 1,264 ordinary tests passed; the required real-clink job also passed all 1,266 tests. Both failed solely because 99.99% line coverage fell below the unchanged 100% threshold. Downloaded Node log lines 4085, 4132–4133 and real-clink log lines 4188, 4235–4236 identify two uncovered controls: a private community declared public and an ordinary photo-download rejection. Both controls now have meaningful regression assertions. Security audits, CodeQL, links, desktop/web builds and the production Docker build passed in this run. Final-head CI results are recorded on PR 141.

The production Docker image was built locally with the supported Rust clink and actual Tesseract eng/rus/vie language models. [The reproducible synthetic-poster smoke test](../../../examples/telegram-ocr-smoke.mjs) extracted 13 million VND/month using sparse-text mode 11. An initial cold/contended run hit the bounded 15-second OCR timeout; a single-thread run and a default-thread replay passed. This does not establish the cause of the first timeout or prove recognition of the unavailable private poster. Tesseract documents `OMP_THREAD_LIMIT=1` as an option for managing OpenMP overhead during concurrent OCR. [Tesseract FAQ](https://tesseract-ocr.github.io/tessdoc/FAQ.html), [benchmark guidance](https://tesseract-ocr.github.io/tessdoc/Benchmarks.html).

The same historical log reports missing release prerequisites: NPM_TOKEN bootstrap, Docker Hub image/username/token configuration. GitHub secret/variable listings and release listings were empty during this investigation. A fresh anonymous npm registry query returned E404 for the package, and a local release-mode preflight refused release (0 verified, 2 failed, 1 unknown). These are external deployment configuration requirements, not parser defects. No token can be generated from repository code, and no release can be honestly declared successful without registry credentials and publication identities.

Re-run local checks with the verified Rust binary on PATH:

```sh

npm run check
PATH=/path/to/rust-clink/bin:$PATH REQUIRE_REAL_CLINK=1 npm test
PATH=/path/to/rust-clink/bin:$PATH REQUIRE_REAL_CLINK=1 npm run test:coverage

```

The protected live audit needs an authorized Telegram user session, public-cohort selection, real Tesseract models and Rust clink. Run it with a new private state directory (or --new-pass), at least three months, no message cap and the existing credential-file options. Retain exact window/cohort identities, compare publication-time parser coverage, and verify checkpoint/storage parity. Do not reuse a previously complete two-month report as proof of the new rolling-90-day-history release gate. Real-image review and successful release-mode preflight/publication are still prerequisites before merging the full closing-reference block.

## Release acceptance procedure

The existing [registry configuration guide](../../deployment.md#registry-configuration) applies unchanged. Provide repository variables `DOCKERHUB_IMAGE` and `DOCKERHUB_USERNAME` and the authorized write credential `DOCKERHUB_TOKEN`. Bootstrap the absent npm package with the supported `NPM_TOKEN` secret, then register `konard/vietnam-accomodation-search` and `release.yml` as its npm trusted publisher. Secrets stay in owner-managed settings.

For the exact release commit, retain the successful **release-mode** preflight, published npm version and integrity, GitHub release URL/tag/commit, OCI index digest and both native platform manifest digests. Run the existing published-package smoke test against the registry artifact in a clean directory and verify the immutable and latest image identities. A local image build, report-mode preflight or PR test matrix does not replace any of these publication checks. Issue 122 remains an acceptance blocker until this evidence exists; merging the required closing-reference block earlier would close it prematurely.
