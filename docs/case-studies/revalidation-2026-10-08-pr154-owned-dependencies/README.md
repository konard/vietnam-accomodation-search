## Public-history and semantic limits

The [previous report](../revalidation-2026-10-08-pr149/README.md#at-least-90-days-of-public-history) documents the complete checksum-verified exact 90-day baseline and full production-parser replay. Between that production revision and PR154, only `src/offers.js` and the new `src/offer-url-identity.js` change; acquisition, message parsing, classification and album assembly are unchanged. This audit does **not** claim to have rerun the entire baseline parser again.

A fresh uncapped real-session catch-up completes every selected public source through the current frozen endpoint. Every newly retained message is accounted for by current production analysis, with zero parser exceptions or age-gate losses. The baseline plus all intervening frozen windows are independently rechecked for page checksums, source identity, checkpoint completion, timestamp bounds, contiguous window endpoints and duplicate source/message identities. No overlap or checksum failure is found. Detailed cohort/workload figures remain in local private evidence rather than upstream issue bodies.

Four albums cross a frozen-window boundary. Their combined retained members are reparsed using production assembly, preserving their offers without parser exceptions. A phase-isolated captionless count is not an independent unresolved-rental count; claiming zero cross-boundary albums would be false.

Important limits remain: historical new-message deltas do not resynchronize every earlier edit/deletion; posts deleted before initial retrieval cannot be recovered; unsupported non-photo media and unreviewed captionless materials remain. The live archive is not fully human-labelled. Zero measured FP/FN in the reviewed corpus does **not** establish globally zero FP/FN, perfect unit reconciliation or complete media extraction.

The real poster correctly retains `reviewRequired=true` / `ocr-fields-unverified`; the map has insufficient rental evidence. These are useful warnings, not errors to suppress. Earlier public HTML-preview completeness/partial-history evidence is referenced in the preceding report, not claimed as a fresh exact-revision preview run here.

The isolated retained-real-journal roundtrip **passes again**, using the actual pinned clink, production-default sharding, complete fresh-store domain/trace/normalized-offer readback and resource guards. No parser replay, runtime suite or Docker build/check runs concurrently with this projection/readback. Its newly created temporary projection/reference state is cleaned up; the original journal is preserved. A passing representative journal is not complete protected acquisition + OCR + durable projection acceptance; [issue 143 remains reopened](https://github.com/konard/vietnam-accomodation-search/issues/143#issuecomment-6059812641).

Three initial diagnostic failures were setup errors, corrected and rerun rather than reported as product defects: restricted sandbox process/loopback checks; forcing Deno manual node_modules mode after npm ci removed Deno-resolved types; and calling nonexistent TelegramClient.close instead of its documented destroy method. Normal CI-compatible Deno and the corrected hardened-container probe pass. The unsupported default host Node 20 is not used for acceptance.

The documented Docker browser configuration disables Chromium's sandbox inside an already hardened non-root/read-only/capability-dropped container. This is an explicit deployment security tradeoff, not an upstream error to hide via automatic fallback. Container checks are local Linux/arm64 only.

Original histories/journals and user-owned untracked transcripts are preserved. Only owned Telegram test messages and newly created disposable projection state are cleaned up. Remaining work is tracked through issues: complete protected-cohort durable ingestion, authorized exact-revision publication/native-platform clean installation, broader independently labelled media/semantic evaluation, and fix/retest the confirmed upstream contracts before deleting application safeguards.
