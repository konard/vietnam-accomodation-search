## Ninety-day and accuracy limits

[Retained-history replay](../../../experiments/telegram-retained-history-replay.mjs) revalidates the entire retained normalized-message archive, not only new deltas. It assembles the combined windows before analysis, including albums crossing frozen boundaries. Posts older than the current 90-day age gate are correctly rejected as current offers while historical extraction remains separately accounted for.

This is **not** proof of complete native acquisition → OCR → graph projection → real notification for the entire protected cohort. The default rolling event budget is smaller than that cohort; intentional event-retention degradation is distinct from #159's silently torn graph. Original journals and prior checkpoint state are preserved, not restarted destructively.

Text-only replay does not recover omitted message entities, perform fresh OCR on every image, support every non-photo media type, resynchronize every old edit/deletion, or recover messages deleted before initial retrieval. Captionless materials lack independently reviewed truth. Zero measured FP/FN in a reviewed corpus therefore cannot establish globally zero FP/FN or fully parsed messages. Correct `reviewRequired` / unverified-OCR warnings must remain visible rather than be suppressed to manufacture a clean result.

The [real-source workflow experiment](../../../experiments/telegram-real-source-workflow-e2e.mjs) now observes original native SDK media IDs, verifies fresh-store event/body/raw-material and graph-reference integrity, then exercises production subscription delivery and restart deduplication without seeding synthetic offers. It requires explicit manual opt-in, a new `e2e` directory, real clink and an explicitly supplied session-converter module. Resource floors prevent exhausting the disk. A failure at media preservation stops the later notification acceptance instead of falsely passing text-only output.
