# Repository issue 100: issues #94–#99, requirements and evidence

This report covers [issue 100](https://github.com/konard/vietnam-accomodation-search/issues/100) and [PR 101](https://github.com/konard/vietnam-accomodation-search/pull/101). The sub-issues cite main `49dcb18`. Research and verification date: 2026-10-05. Every sub-issue body was read, and none of #94–#100 had comments. Live runs used the host network, an empty `DATA_DIRECTORY=$(mktemp -d)` and `BROWSER_NO_SANDBOX=1`. Live text was anonymised before anything was committed. Raw previews and samples stayed outside the repository.

**What this branch proves and what it does not.** #94–#98 are fixed in code, and every fix has a test that fails without it. The live product search returns offers again and finishes within its 3-minute budget. The cohort runs, field metrics and live search below are agent-run, not owner QA. The reviewed corpus was reviewed by the agent against the post text, not by a human. #99 needs owner credentials and stays open (see [below](#issue-99-owner-inputs)).

## Issue 94: product search returned nothing

Root cause, confirmed on main: `validKind()` accepts only `/^[a-z][a-z\d-]*s$/`, and the browser cooldown collection was `browser-domain-cooldown`. Every source threw at its first cooldown read. `SearchService` turned 60 failures into an empty result, and the CLI exited 0.

Product-path field checks found two defects that the parser-only metrics missed:

- **34 merged offers.** Offers were merged by `propertyId`, and a property id was read from any number after a label. On the reviewed sample this gave 166 unique offers out of 200; after `2d5871c` it gives 200 ([experiments/issue-94-property-id-merges.mjs](../../../experiments/issue-94-property-id-merges.mjs)).
- **alonhadat 15 → 3.** Cards without a matching title selector fall back to their first line, which on some sites is a section label such as `CHO THUÊ`. Same-sized units in one place then shared a fingerprint. In cohort run 3, alonhadat stored 3 of the 15 offers it collected; in run 5 it stored 15 (`371eb82`).

Other defects found in live runs:

- **Renderer crashes.** With the host's 64 MB `/dev/shm`, Chromium crashed on heavy booking pages, and the pool reused the crashed page for every following source. One run had 38 of 60 sources fail with `Target crashed` ([live-search-before-shm-fix.md](live-search-before-shm-fix.md), [default](issue-96-renderer-crash-default.log) and [no-shm](issue-96-renderer-crash-no-shm.log) logs). `--disable-dev-shm-usage` gave 0 failed loads in 3 runs, against 9–12 without it. Crashed workers are now replaced.
- **Store parse time.** Each per-source save parsed the whole offer collection the previous save had written. The store now keeps the records of the text it last wrote, and the search-service replay went from 11.6 s to 4.8 s ([experiments/issue-100-offer-roundtrip.mjs](../../../experiments/issue-100-offer-roundtrip.mjs) checks that a remembered collection equals a fresh parse).

## Upstream suggestions (not filed)

- **browser-commander**: Playwright's own Chromium launcher passes `--disable-dev-shm-usage`, but browser-commander's real-browser launch does not. On hosts with a small `/dev/shm`, every page crashes. This branch passes the switch itself.
- **links-notation**: parsing 84 offers (about 4 MB of associative records) takes about 1.3 s with 0.22. This branch avoids re-parsing what it wrote, but a faster parser would help every reader.

## Known limits

- t.me public previews share one domain, so the Telegram sources run in one paced lane. Most of a cold search's budget goes to that lane, and Telegram sources still queued at 180 s are reported as `pending`.
- 21 Telegram default sources have no reviewed sample. Many are groups, which have no `t.me/s` preview.
- Availability rests on 9 unavailable cases. Its 1.000 is weak evidence, and more sold-out posts should be reviewed.
- The corpus was reviewed by the agent against the post text. Some expectations may need a human pass, for example `nha-trang-renting-005`, where the card is ambiguous between a studio and one bedroom.
- Live sites change daily, so the live mode of the search-service audit can match fewer reviewed cards over time, and the corpus needs refreshing.
