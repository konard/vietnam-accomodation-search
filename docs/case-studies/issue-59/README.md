## Research and component choices

- **`clink` name normalization (#55).** The pinned Rust `link-cli` trims every line of an imported document and drops blank lines ([`normalize_links_notation`, `rust-v0.2.10` line 152](https://github.com/link-foundation/link-cli/blob/rust-v0.2.10/rust/src/lino_database_input.rs#L152)), then trims each name and strips trailing colons ([`normalize_identifier`, line 134](https://github.com/link-foundation/link-cli/blob/rust-v0.2.10/rust/src/lino_database_input.rs#L134)). [`rust-v0.2.11`](https://github.com/link-foundation/link-cli/blob/rust-v0.2.11/rust/src/lino_database_input.rs#L134) is identical. A value that ends in a newline or space, contains a blank or indented line, CRLF, or is empty is therefore imported under a different name. The exported database then shows one missing and two unexpected two-value links, exactly the shape of the retained failure. Upgrading `clink` does not help.
- **links-notation quoting (#55).** [`Link.escapeReference` in `js_0.20.0`](https://github.com/link-foundation/links-notation/blob/js_0.20.0/js/src/Link.js#L84) writes a name that contains both quote kinds as `'…\'…'`, but the parser does not read that escape back and reports a syntax error (`experiments/links-notation-mixed-quotes.mjs`).
- **Chosen fix.** Schema v3 percent-encodes only the characters that those two steps rewrite, and decodes them on read. The text remains canonical, and verification stays exact. Alternatives were rejected: relaxing verification to compare normalized names would hide genuine link loss, which the issue forbids, and a patched `clink` cannot be pinned until upstream releases it.
- **Bot API peers (#56).** The Bot API accepts `@username` only for public channels and supergroups. A user's username returns 400 `Bad Request: chat not found` before anything is sent ([zeroclaw-labs/zeroclaw#496](https://github.com/zeroclaw-labs/zeroclaw/issues/496) shows the same response). The runtime classified this as `malformed`, so a combined runtime never used its user fallback for availability inquiries to an owner's `@username`. It is now an `entity` failure.
- **Publication (#54).** [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) needs an existing package, so the first publish still needs the owner's scoped bootstrap `NPM_TOKEN`. The failing check is [run 36470214228](https://github.com/konard/vietnam-accomodation-search/actions/runs/36470214228). Registry smoke tests, integrity checks, and provenance checks already exist in `scripts/smoke-test-package.mjs` and `scripts/collect-release-identity.mjs`.
- **Unhealthy candidate (#57).** The drill uses [Compose `extends`](https://docs.docker.com/compose/how-tos/multiple-compose-files/extends/) to reuse the production service unchanged and override only its health check. Production files are not edited.

## Draft upstream issues

Not filed; post them only with the maintainer's approval.

> **link-cli: LiNo import trims names and lines, so exact round-trips fail.** In `rust/src/lino_database_input.rs` (tags `rust-v0.2.10` and `rust-v0.2.11`), `normalize_links_notation` trims every line and drops blank lines, and `normalize_identifier` trims names and strips trailing colons. A quoted name such as `'a '`, `'x:'`, a multi-line value with an indented or blank line, or `''` is imported under a different name, so `export` no longer equals the input. Proposal: keep quoted names verbatim (only unescape the quotes) and normalize only unquoted structure.

> **links-notation: a reference with both quote kinds does not round-trip.** `Link.escapeReference` (`js_0.20.0`) writes `a'b"c` as `'a\'b"c'`, but the parser does not treat `\'` as an escape: `(` + that reference + `: x)` fails with a syntax error (`experiments/links-notation-mixed-quotes.mjs`). Proposal: support backslash escapes inside quoted references, or pick a delimiter that never needs escaping.
