## Release failure reproduced and repaired

The release jobs in [run 36160222510](https://github.com/konard/vietnam-accomodation-search/actions/runs/36160222510) and [run 36174042368](https://github.com/konard/vietnam-accomodation-search/actions/runs/36174042368) prepared `0.12.3`, then failed before commit at staged-file inspection with `ERR_INVALID_ARG_TYPE`: `TextDecoder.decode` was given a `command-stream` `CapturedReadable`, rather than bytes. In the locally downloaded first log the error is at line 18149; in the second, line 17920.

`version-and-commit.mjs` now reads the command result with `await stagedResult.text()` before parsing Git's NUL-delimited paths. A real `command-stream` and Git integration test first failed with the same exception, then passed after the change. The fixture contains a newline in a staged filename, so accidental line splitting cannot pass. The fix stops at the first diagnosed release failure; publication and downstream exact-artifact gates still need a release workflow run.

Local checks on this branch: Node 24 **791/791**, Node 22 **791/791**, Bun **791/791**, Deno **704/704**, and `npm run check` passed with Rust `clink` 0.2.10 available. The Docker Go-template argv regression also passed on both local Node versions. Its earlier reported local failure is currently not reproducible; the pushed PR matrix passed on Node, Bun, and Deno across Linux, macOS, and Windows. Docker build, lint, documentation, security, and link checks also passed. Release jobs were skipped on the PR branch. A fresh polite ten-route Browser Commander run classified five successful, four challenged, and one parse-incomplete route. Only these sanitized counts and classifications are recorded here; the raw trace remains in private temporary storage.

## Relevant existing components and choices

- [Node child process documentation](https://nodejs.org/api/child_process.html) specifies direct argument arrays and `execFile` without a shell. The current release command uses `command-stream`; its captured result must be decoded through its own API. The focused fix preserves this repository's existing `use-m`/`command-stream` boundary.
- [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) supports GitHub Actions OIDC with Node at least 22.14 and npm at least 11.5.1. It requires an exact repository/workflow association; a package owner must create/configure the first package and remove bootstrap token access afterward.
- [Rust link-cli](https://github.com/link-foundation/link-cli) supports persistent databases, LiNo import/export, automatic references, and Rust library embedding. Incremental import or a library-level bulk path is worth benchmarking, but exact export verification remains necessary.
- [mtcute's Node guide](https://github.com/mtcute/mtcute/blob/master/docs/guide/index.md) documents the native Telegram client that the production user path already uses. A GramJS driver session is a distinct format and needs a separate login for native runtime acceptance.
- [Docker image inspect](https://docs.docker.com/reference/cli/docker/image/inspect/) supports a Go-template format value; the existing deployment code sends it as one argument. [Playwright locators](https://playwright.dev/docs/locators) can support visible detail-page inspection through Browser Commander, but cannot justify inventing semantic fields absent from the page.
