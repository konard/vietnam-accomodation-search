# Issue 20 requirement inventory and design

This document is the implementation plan and traceability record for umbrella
[Issue #20](https://github.com/konard/vietnam-accomodation-search/issues/20).
It covers every numbered implementation requirement in Issues #12 through #19.
The issue bodies and all comments were re-read on 2026-09-22; there were no
comments on any of the nine issues at that time.

Status terms:

- **Automated** means the contract has deterministic local tests.
- **Historical live** means a privacy-safe observation from the earlier audit
  remains valid evidence, but is not represented as a post-change run.
- **Pending live** means the implementation and manual runner exist, but the
  required release, credentials, or mutable public-site observation does not.
  A pending gate is deliberately not converted into a fixture pass.

## Umbrella Issue #20

All code, tests, documentation, evidence handling, and workflow changes are in
PR #21. Its final description contains one independent closing line for every
sub-issue plus the umbrella issue:


No requirement is delegated to another implementation PR. The two necessarily
future observations—an actual next Release audit and mutable-site credentialed
E2E—are represented by executable manual gates whose state is `pending`, as
the issues explicitly require when the release or credentials do not exist.
