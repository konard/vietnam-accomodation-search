## #43: bounded and complete 40-source Telegram audit

| Requirement                                                   | Current result and completion plan                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Profile the actual 16 MB snapshot and isolate its cost        | A private real snapshot is unavailable here. A reproducible synthetic microbenchmark showed 100 named links: bare import/export 0.33 s, synchronous transaction import/export 3.89 s, asynchronous transaction import/export 3.55 s. Bare 1,000 links took 9.97 s; transactional 1,000-link probes were interrupted after 260 s (sync) and 51 s (async) without completion. This implicates the transaction layer but does not establish a 16 MB budget. Reprofile on the retained real candidate before claiming acceptance. |
| Incremental/transactional large writes and exact verification | The binary mirror uses an immutable candidate and atomic pointer, so its scratch import no longer needs per-link synchronous transactions. It still verifies full LiNo export and binary checksum before activation. The complete snapshot is still rebuilt per source; design an append/upsert strategy only after profiling it against edits/deletes and exact export semantics. [link-cli import/export and transactions](https://github.com/link-foundation/link-cli) are the relevant native mechanisms.                 |
| Bounded child and redacted telemetry                          | `clink` now has heartbeat, ten-minute deadline, TERM then KILL escalation, and a `storage-timeout` code. Telemetry reports phase, elapsed time, status, and stderr byte count without raw listing text.                                                                                                                                                                                                                                                                                                                       |
| Pre-projection privacy-safe checkpoint and idempotent resume  | A private `0600` checksummed source journal stores the parsed batch before binary projection. On retry, the same window is replayed from the journal; successful checkpoint commit removes it. Test interruption after each write boundary and verify no history reread before accepting this gate.                                                                                                                                                                                                                           |
| Candidate retention and recovery                              | Failed candidates retain canonical LiNo and redacted failure metadata. Any verified candidate is reused after an interrupted pointer write; stale partial candidates are moved aside before rebuilding. Add fault-injection coverage for all crash boundaries.                                                                                                                                                                                                                                                                |
| Exactly 40 non-private sources, full rolling two months       | The existing selector excludes private/user dialogs. A fresh credentialed run must show exactly 40 selected public/community sources, no caps, and a mode-`0600` sanitized report.                                                                                                                                                                                                                                                                                                                                            |
| Human-reviewed parsing and all terminal states                | Review anonymized misses and add fixtures until accepted/excluded/review/error outcomes cover every material and every useful segment. Preserve edits/deletes, albums, OCR/media, identities, contact, location, one/two-sided ranges and periods, and provenance as typed links.                                                                                                                                                                                                                                             |
| Strict gate and second-run idempotence                        | Require active bot/user, folder discovery, zero source/truncation/segment/terminal errors, reviewed precision and recall of 1, no unresolved media, complete expected fields, typed storage CRUD/query/round-trip, then rerun to prove checkpoint/cache reuse. This cannot be asserted without credentials and the complete live cohort.                                                                                                                                                                                      |

The canonical LiNo file remains authoritative. A timed-out binary candidate is never accepted as a verified mirror. The 16 MB local budget, bounded memory measurement, full 40-source acceptance, and second-pass idempotence remain open.

## Repository-wide application

The release fixture change covers every subprocess case in the suite. The Docker build identity change covers direct Compose, deploy helper, and Docker Hub action builds. Browser status classification is at the shared manual audit boundary; rental route and adapters are versioned in the shared source registry. The `clink` execution and candidate recovery changes are in `LinkCliMirror`, so all binary-mirrored collections use the same bounds and verification. The source journal is intentionally limited to the private manual Telegram audit, whose history collection must not repeat after a projection failure.
